# 포크레인(굴착기) 교육 시뮬레이터 — 타당성 검토 및 구현 계획

> 기준 문서: `포크레인작동.md` (간략 기획서)
> 작성일: 2026-11-24 (같은 날 보완: 키보드 조작, 2단계 과정 구조, 시뮬레이션 핵심 설계, P0 상세, 교육 효과 검증)
> **전제:** 구현의 대부분을 Claude Code(AI 개발 보조)와 소수 개발자가 진행한다고 가정했다.
> 이 전제가 바뀌면(3D 아티스트가 있는 전문 개발팀, 최고 수준 그래픽이 필요한 경우) 엔진 선택이 바뀐다. 자세한 내용은 §3.3에 있다.

## 1. 결론: 구현 가능

기획서의 네 축인 **단계별 난이도, 운전석 UI, 레벨별 현장, 수료증/뱃지**는 모두 현재 기술로 구현할 수 있다.
다만 "얼마나 실제에 가깝게" 만들지 충실도 등급을 먼저 정해야 일정과 비용이 정해진다.

| 구분 | 1차 목표 (이번 계획 범위) | 1차 범위에서 제외 (추후 검토) |
|---|---|---|
| 조작 | 실제 레버 패턴의 2-조이스틱 조작, 주행 페달·레버, 안전레버, **키보드 조작(정식 지원)** | 실제 굴착기 운전석 하드웨어 일체(좌석, 콘솔 개조) |
| 물리 | 유압 실린더 속도 기반의 붐·암·버킷 운동, 높이맵 지형 굴착, 단순 토사 부피 모델 | 입자(DEM) 단위 토사 시뮬레이션, 토질별 정밀 저항 |
| 화면 | 1~3 모니터 운전석 시점, 외부 시점(교육용) | 모션 플랫폼, VR(선택 옵션으로만 고려) |
| 인증 | 기관 내부 수료증, 뱃지, QR 진위 확인 | **국가기술자격 대체·인정 아님** (별도 인증 절차 필요) |

**가장 큰 기술 위험은 "버킷-토사 상호작용"이다.** 퍼 담기, 흘림, 덤프가 자연스럽지 않으면 교육 효과가 없다.
그래서 메뉴, 계정, 수료증보다 **이 부분을 먼저 검증(P0, §8.1)** 하는 일정으로 짰다. 동작 방식은 §3.4에 정리했다.

## 2. 형태 결정: 웹 기술 기반 데스크톱 앱 (+ 웹 배포 겸용)

- **주 형태:** Windows 데스크톱 앱. 교육장 PC에 설치하고, 오프라인 실행과 조이스틱·페달 연결을 지원한다.
- **보조 형태:** 같은 코드를 웹 브라우저로 배포한다. 이론과 기초 레벨 예습, 원격 체험용이다.
- 한 코드베이스로 두 형태를 모두 낸다. 데스크톱 패키징은 Tauri(경량)를 1순위, Electron을 대안으로 둔다.

웹 단독으로 하지 않는 이유는 교육장 환경 때문이다. 키오스크 모드, 다중 모니터 전체화면, 오프라인, 장비 고정 설정이 필요한 환경에서는 데스크톱 패키징이 안정적이다.

## 3. 구현 기술

### 3.1 기술 스택 (권장안)

| 계층 | 기술 | 선택 이유 |
|---|---|---|
| 언어 | **TypeScript** | 시뮬레이터, UI, 서버를 한 언어로 통일하고 타입 안정성을 확보 |
| 3D 엔진 | **Babylon.js** (WebGL2/WebGPU) | 산업·교육용 시뮬레이터 사례가 많고, 물리(Havok) 통합, 다중 카메라·뷰포트, 입력 장치 지원 |
| 물리 | **Havok (Babylon 공식 플러그인 `@babylonjs/havok`, WASM)** | 차체·트럭·장애물 충돌. 붐·암·버킷은 물리 조인트가 아니라 **운동학(실린더 속도) 모델**로 직접 계산 |
| 지형 굴착 | 높이맵 지형 + 자체 토사 부피 모델 | 실시간 변형이 가볍고, 굴착량을 수치로 채점 가능 |
| 입력 | **키보드 이벤트 + Gamepad API** + HID 매핑 레이어 | 키보드, USB 조이스틱 2개, 페달, 게임패드를 모두 같은 "가상 레버" 입력으로 변환 |
| UI(메뉴·대시보드) | React + Vite | 레벨 선택, 결과 화면, 강사용 관리 화면. 문구는 처음부터 다국어 구조(한국어 우선)로 분리해, 외국인 근로자용 언어 추가에 대비 |
| 데스크톱 패키징 | **Tauri** (대안: Electron) | 오프라인 설치형, 키오스크 모드 |
| 서버 | Node.js (Fastify) + **PostgreSQL** | 훈련생, 기록, 수료증 관리. 교육장 로컬 서버 또는 클라우드 |
| 오프라인 저장 | SQLite (로컬) → 서버 동기화 | 네트워크가 끊겨도 기록 보존 |
| 수료증 | PDF 생성(서버) + **QR 진위 확인 페이지** | 출력·제출용 |
| 테스트 | Vitest(물리·채점 단위 테스트), Playwright(화면 흐름) | 채점 로직은 반드시 자동 테스트 |

### 3.2 핵심 모듈 구조

장비 독립 코어를 둔다. 옆 폴더 `Jigecha`(지게차)를 같은 구조로 확장할 수 있게 하려는 것이다.

```
core/            ← 장비 공통 (지게차 시뮬레이터에서도 재사용)
  sim/           고정 주기 시뮬레이션 루프, 입력 기록·재생
  terrain/       높이맵 지형, 토사 부피 계산
  input/         키보드·조이스틱·페달 → 가상 레버 변환, 레버 패턴 설정, 데드존/감도 보정
  scoring/       채점 엔진 (규칙 정의 → 이벤트 수집 → 점수 산출)
  curriculum/    레벨·과제 정의(JSON), 해금 조건
  session/       훈련 기록, 리플레이 로그
  certificate/   뱃지·등급·수료증 발급
equipment/excavator/
  kinematics     붐·암·버킷·선회·주행 모델 (유압 실린더 속도 제한, 부하에 따른 감속)
  bucket-soil    버킷 내 토사 부피, 흘림, 덤프
  cab            운전석 모델, 계기판(엔진 RPM, 연료, 경고등), 미러
sites/           레벨별 현장 (평지 연습장, 시험 코스, 도로 굴착, 상하수도, 경사면, 상차 작업 …)
apps/
  simulator      훈련생용 (데스크톱/웹)
  admin          강사·기관용 대시보드
  server         API, DB, 수료증 발급·검증
```

### 3.3 엔진 선택의 대안: 언제 Unity로 바꾸나

| 조건 | 권장 |
|---|---|
| Claude Code 위주 개발, 빠른 반복, 웹 배포도 필요 | **Babylon.js + TypeScript (본 계획)** |
| 3D 아티스트·Unity 개발자 보유, 고품질 그래픽과 실장비급 콘솔 연동이 최우선 | Unity 6 (C#) + 별도 웹 LMS |
| 영화급 그래픽, 대형 예산 | Unreal Engine 5 |

Unity로 바꿔도 §4~§7의 커리큘럼, 채점, 수료증 설계는 그대로 쓸 수 있다.
웹 기술을 권장하는 이유는 하나다. AI 보조 개발로는 브라우저에서 바로 실행하고 확인할 수 있는 스택이어야 검증 주기가 짧다. Unity는 씬·프리팹 작업 대부분이 에디터 수작업이다.

### 3.4 시뮬레이션 핵심 설계

교육 효과를 좌우하는 부분이라 방식을 미리 정해 둔다. 모든 수치는 파라미터 파일로 빼서 현업자 피드백으로 조정한다.

**① 고정 주기 시뮬레이션**
- 시뮬레이션은 화면 프레임과 분리해 **고정 주기(예: 60Hz)** 로 돈다. PC 성능이 달라도 같은 입력이면 같은 결과가 나와야 채점이 공정하다.
- 기록은 **입력 스트림 + 주기적 상태 스냅샷**으로 저장한다. 리플레이는 이 기록으로 재생한다. 물리 엔진(Havok) 부분은 PC마다 미세하게 다를 수 있어 스냅샷으로 보정한다.

**② 작업 장치(붐·암·버킷·선회) 운동 모델**
- 레버 기울기 → 유량 요구 → **실린더 신장 속도** → 관절 각도 순으로 계산한다. 관절을 물리 엔진에 맡기지 않아 떨림이나 폭주가 없다.
- **유량 분배:** 여러 동작을 동시에 하면 펌프 유량을 나눠 쓰므로 각 동작이 느려진다. 실장비의 복합 동작 감각을 재현하는 핵심이다. 엔진 RPM과 작업 모드가 전체 유량을 결정한다.
- **가속·지연:** 레버 입력 후 짧은 응답 지연과 가감속을 둔다. 선회는 관성이 커서 멈출 때 밀림이 생긴다.
- **굴착 저항:** 버킷이 땅에 깊이 박힐수록 실린더 속도가 줄어든다. 너무 깊게 파면 멈추는 상황을 재현한다.
- 실린더 끝(스트로크 끝)에 닿으면 정지하고, 장비 제원(작업 반경, 최대 굴착 깊이)은 실제 장비 카탈로그 값으로 설정한다.

**③ 지형과 토사 모델**
- 지형은 **높이맵**으로 표현한다. 작업 구역은 촘촘하게(예: 5~10cm 격자), 나머지는 거칠게 한다.
- **굴착:** 버킷 날 끝이 지면 아래로 굴착 방향으로 움직이면 그 경로의 흙을 높이맵에서 깎아 버킷 안 부피로 옮긴다. 이때 흙이 부풀어 부피가 늘어나는 비율(팽창률, 약 1.2~1.3)을 적용한다. 버킷 용량(평적·산적)을 넘으면 더 담기지 않고 넘친다.
- **흘림:** 버킷 입구가 기울어지거나 선회·정지가 급하면 일정 비율이 떨어진다. 떨어진 위치와 양이 "흘림" 채점에 그대로 쓰인다.
- **덤프·쌓기:** 쏟은 흙은 떨어진 지점에 쌓이고, 흙더미가 안식각(약 30~35°)보다 가파르면 옆으로 흘러내린다.
- **부피 보존:** 깎은 양, 버킷 안의 양, 쌓인 양, 흘린 양의 합계가 맞는지 매 과제 검사한다. 채점 신뢰성의 기준이다.

**④ 차체·안정성**
- 크롤러 주행은 좌우 궤도 속도 차이로 회전한다. 경사지에서는 미끄러짐을 단순 모델로 넣는다.
- **전도 위험:** 장비 무게중심(버킷 하중 포함)이 궤도 접지 범위를 벗어나는지 계속 검사한다. 위험 단계에서는 경고하고, 넘으면 전도 사고로 처리한다(W3 경사지 과제).

### 3.5 3D 모델·현장 에셋 확보

AI 보조 개발로도 코드는 만들 수 있지만, 사실적인 장비·운전석 3D 모델은 따로 확보해야 한다.

| 에셋 | 확보 방법 (우선순위) | 비고 |
|---|---|---|
| 굴착기 외형 (붐·암·버킷 분리 구조) | ① 상용 3D 모델 구매(상업 이용 라이선스) ② 외주 제작 | 관절별로 분리된 모델이어야 함. 특정 제조사 상표·로고는 제거 |
| 운전석 내부 (레버, 계기판, 창틀) | 외주 제작 또는 구매 모델 수정 | 실제 운전석과 레버 위치가 맞아야 교육 효과가 있음 |
| 현장 소품 (덤프트럭, 라바콘, 배관, 작업자) | 상용·무료(CC0) 에셋 | 라이선스 목록을 문서로 관리 |
| 지형 재질·하늘·날씨 | 무료(CC0) 텍스처, 절차적 생성 | |
| 효과음 (엔진, 유압, 굴착, 경고음) | 상용 음원 또는 실장비 녹음 | 엔진 RPM과 부하에 따라 소리가 바뀌어야 함 |

- P0은 단순한 형태(박스·실린더 조합)로 개발하고, 실제 모델은 P1부터 바꿔 넣는다. 모델 교체가 코드에 영향을 주지 않도록 관절 이름 규칙을 먼저 정한다.

## 4. 조작계 설계 (실제 운전석 재현)

### 4.1 조작 장치

| 장치 | 기능 | 1차 하드웨어 |
|---|---|---|
| 좌 조이스틱 | 선회(좌우), 암(전후) ※ 패턴에 따라 다름 | USB 비행/산업용 조이스틱 |
| 우 조이스틱 | 붐(전후), 버킷(좌우) ※ 패턴에 따라 다름 | USB 조이스틱 |
| 주행 레버/페달(좌·우) | 좌우 궤도 독립 주행, 제자리 회전 | USB 페달 또는 조이스틱 축 |
| 안전 레버(락 레버) | 올리면 모든 유압 조작 차단 | 버튼/스위치 매핑 |
| 엔진 RPM 다이얼, 작업 모드 | 속도와 정밀도 조절 | 노브/버튼 |
| 경음기, 시동키, 안전벨트 | 안전 절차 채점 대상 | 버튼 |

- **레버 패턴은 설정으로 바꿀 수 있게 한다.** 국내 교육장에서 쓰는 패턴, ISO 패턴 등을 프리셋으로 넣고 기관별로 선택한다. 국내 표준 패턴은 확인 필요.
- 아날로그 입력은 **비례 제어**로 처리한다. 레버를 기울인 만큼 실린더 속도가 결정되므로, 미세 조작 숙련도를 측정할 수 있다.
- 입력 방식은 **조이스틱, 키보드, 게임패드(듀얼 스틱)** 세 가지를 지원한다. 키보드는 대체 수단이 아니라 정식 입력 방식이다(§4.2).

### 4.2 키보드 조작

조이스틱이 없는 교육장, 개인 PC 예습, 웹 체험에서도 전 과정을 진행할 수 있게 키보드를 정식 입력 방식으로 지원한다.

**설계 원칙: 키보드는 "가상 레버"를 움직인다**
- 키는 기능(붐, 암 등)에 직접 연결하지 않는다. 대신 **좌·우 가상 조이스틱의 방향**에 연결한다.
- 그러면 §4.1의 레버 패턴 설정이 키보드에도 그대로 적용된다. 키보드로 익힌 손의 감각이 실제 조이스틱으로 이어진다.

**기본 키 배치 (안)** — 모든 키는 설정 화면에서 바꿀 수 있다.

| 키 | 가상 장치 | 기능 (ISO 패턴 기준 예시) |
|---|---|---|
| W / S | 좌 레버 앞 / 뒤 | 암 펴기 / 암 당기기 |
| A / D | 좌 레버 좌 / 우 | 좌 선회 / 우 선회 |
| I / K | 우 레버 앞 / 뒤 | 붐 내리기 / 붐 올리기 |
| J / L | 우 레버 좌 / 우 | 버킷 오므리기(굴착) / 버킷 펴기(덤프) |
| ↑ / ↓ | 주행 레버 양쪽 | 전진 / 후진 |
| ← / → | 주행 레버 좌우 반대 | 제자리 좌회전 / 우회전 |
| Shift (누른 채) | 미세 조작 | 모든 동작 속도 30~50% |
| F | 안전레버 | 잠금 / 해제 |
| Space | 경음기 | |
| R | 시동 키 | 시동 / 정지 |
| B | 안전벨트 | 착용 / 해제 |
| + / − | 엔진 RPM 다이얼 | 단계 조절 |
| Tab / V | 카메라 | 운전석 · 외부 · 후방 시점 전환 |

- 왼손(WASD)과 오른손(IJKL)이 실제 좌·우 조이스틱 역할을 나눠 맡는다. 두 손으로 동시 조작(복합 동작)을 연습할 수 있다.

**키보드의 한계 보완: 비례 제어 흉내**
- 키보드는 눌림·안 눌림만 있어 조이스틱처럼 "조금만 기울이기"가 안 된다. 다음 방법으로 보완한다.
  - **가속 램프:** 키를 누르고 있으면 가상 레버가 0에서 최대까지 서서히(예: 0.3~0.6초) 기울어진다. 짧게 톡 누르면 조금만 움직인다.
  - **미세 조작 키(Shift):** 최대 기울기를 제한해 정밀 작업을 할 수 있게 한다.
  - **복귀 감속:** 키를 떼면 레버가 바로 0이 되지 않고 짧게 감속한다. 유압 장비의 관성을 흉내 낸다.
- 램프 시간과 미세 조작 비율은 설정값으로 두고, 교육 단계에 맞게 조정한다.

**화면 보조 표시**
- 키보드 모드에서는 화면 구석에 **가상 레버 두 개의 현재 기울기**를 보여 준다. 훈련생이 "지금 레버를 얼마나 밀고 있는지" 눈으로 확인할 수 있다.
- L0~L2에서는 키 배치 안내를 함께 표시한다.

**입력 방식 기록**
- 모든 세션 기록에 입력 방식(키보드 / 조이스틱 / 게임패드)을 남긴다. 부드러움 채점 기준을 입력 방식별로 적용하고(§6), 수료증에 주 입력 방식을 표시한다(§7).

### 4.3 운전석 UI

- 1인칭 운전석 시점: 프레임, 유리창, 좌우 미러, 계기판, 후방 카메라 화면
- 다중 모니터: 정면, 좌측, 우측 창
- 교육용 보조 표시: 레벨이 낮을 때만 켠다. 버킷 궤적, 목표 깊이 가이드, 레버 입력 시각화, 선회 반경 표시

### 4.4 좌석 구성 등급 (안)

같은 프로그램을 기관 예산에 맞춰 세 가지 구성으로 운영한다.

## 5. 교육 과정 및 난이도 설계

### 5.1 설계 원칙

- 레벨이 오를수록 **보조 기능은 줄이고 조건은 늘린다.** 시간 제한, 정밀도, 안전 감점, 환경 변수를 순서대로 강화한다.
- 각 과제는 **합격 기준(점수·시간·필수 안전항목)** 을 갖는다. 기준을 넘으면 다음 과제가 해금된다.
- ① 자격증 과정은 **굴착기운전기능사 실기(작업형: 굴착 작업 + 코스 운전)** 에 맞춘다.
  > ⚠️ 실기 과제의 정확한 치수, 시간, 채점 항목은 큐넷(q-net.or.kr) 공개자료에서 **확인 필요**. 공개 웹 검색으로는 공식 원문을 확인하지 못했고, 시험 시간도 출처마다 다르게 나온다. 확정 전까지 수치는 설정값(JSON)으로 분리해 둔다.

### 5.2 전체 구조: 두 개의 과정

교육은 **① 자격증 취득 과정**과 **② 실무 시뮬레이션 과정**, 두 단계로 나눈다.
①은 굴착기운전기능사 합격이 목표다. ①을 마치면 ②가 열리고, 실제 현장 작업을 연습한다.

```
[① 자격증 취득 과정]                                   [② 실무 시뮬레이션 과정]
 L0 입문 → L1 기초 → L2 복합 → L3 굴착 → L4 주행 → L5 모의 실기시험 ─┬→ W1 → W2 → W3 → W4 → W5
                                     (+ 필기 모의고사, 선택)       │
                                     실제 자격증 보유자 등록 ──────┘  (강사 확인 후 바로 ②로)
```

- **②가 열리는 조건:** ①의 L5 모의 실기시험 합격, 또는 실제 굴착기운전기능사 자격증 보유 등록(강사 확인). 이미 자격증이 있는 재직자는 ①을 건너뛰고 바로 실무 과정을 시작할 수 있다.
- 시뮬레이터는 시험 **준비**를 돕는다. 실제 자격증은 큐넷 시험에 응시해 취득한다.

### 5.3 ① 자격증 취득 과정 (L0~L5)

| 단계 | 명칭(안) | 현장 | 주요 과제 | 보조 기능 | 통과 기준 예시 |
|---|---|---|---|---|---|
| L0 | 입문 | 교육장 가상 강의실 | 장비 구조, 레버 기능 이해, 시동 전 점검 절차 | 전체 | 퀴즈와 절차 100% |
| L1 | 기초 조작 | 평지 연습장 | 단일 레버 조작: 붐 올리기·내리기, 암, 버킷, 선회 | 전체 | 목표 자세 오차 ±10% 이내 |
| L2 | 복합 조작 | 평지 연습장 | 2개 이상 동시 조작, 목표 지점 버킷 정렬 | 궤적 표시 | 목표 링 통과, 시간 제한 |
| L3 | 굴착 작업 연습 | **실기시험 굴착 작업장 재현** | 시험 방식의 굴착 → 선회 → 지정 위치 덤프 반복 | 깊이 가이드 | 적재량, 흘림, 시간 |
| L4 | 코스 운전 연습 | **실기시험 코스 재현** | 시험 코스 주행(전진·후진, 회전), 라인 이탈 방지 | 경로 표시 | 라인 이탈·접촉 없음, 시간 |
| L5 | **모의 실기시험** | 시험장 재현 (굴착 작업 + 코스 운전) | 실제 시험과 같은 순서·시간·채점으로 응시 | 없음 | 시험 합격 기준 준용, **3회 연속 합격** 시 과정 수료 (기준 확인 필요) |

**자격증 과정 전용 기능**
- **모의시험 모드:** 실제 시험처럼 감독관 안내 음성, 제한 시간, 실격 조건을 적용한다. 결과는 실제 채점표 형식으로 보여 준다.
- **약점 연습 추천:** 모의시험에서 감점된 항목(예: 코스 라인 접촉, 덤프 위치 이탈)을 L3·L4의 집중 연습 과제로 연결한다.
- **필기 모의고사 (선택 모듈):** 자격증은 필기와 실기를 모두 통과해야 하므로 필기 대비 문제은행을 둔다. 문제는 자체 제작하거나 이용 허락을 받은 문제를 쓴다. 기출문제 저작권은 확인 필요.
- **시험 응시 안내:** 큐넷 원서 접수, 상시검정 일정 링크를 제공한다.

### 5.4 ② 실무 시뮬레이션 과정 (W1~W5)

자격증 이후 단계다. 시험 코스가 아니라 **실제 공사 현장의 작업 지시**를 받아 수행한다. 보조 기능은 없고, 평가 기준에 **품질(설계 대비 정확도)** 과 **생산성(시간당 작업량)** 이 추가된다.

| 단계 | 명칭(안) | 현장 | 주요 과제 | 통과 기준 예시 |
|---|---|---|---|---|
| W1 | 현장 적응 | 일반 토공 현장 | 작업 지시서 읽기, 터파기(기초 굴착), 덤프트럭 상차(적재 균형), 신호수 수신호 따르기 | 지시 깊이 오차, 트럭 과적·편적 없음 |
| W2 | 관로 작업 | 도로·상하수도 현장 | 정해진 폭·깊이의 트렌치 굴착, 관 매설 후 되메우기 | 체적 정확도, 기존 매설물 손상 0 |
| W3 | 경사·협소지 | 법면(경사면), 도심 협소지 | 경사면 정리, 경사지 주행·작업, 좁은 공간 선회, 건물·차량 근접 작업 | 전도 위험 0, 접촉 0 |
| W4 | 위험 요소 대응 | 고압선·매설물 밀집 현장 | 가스관·통신선 주변 굴착, 고압선 하부 작업, 연약 지반 | 안전사고 0, 경고 구역 침범 0 |
| W5 | 종합 실무 (마스터) | 복합 현장 | 야간·우천·시야 제한, 돌발 상황(작업자 진입, 장비 경고), 하루 작업량 완수 | 품질·생산성·안전 종합 점수 |

**실무 과정 전용 기능**
- **작업 지시서와 도면:** 과제마다 "어디를, 얼마나 깊게, 언제까지" 굴착할지 지시서로 준다. 결과는 설계 지형과 비교해 색으로 보여 준다(파야 할 곳, 과굴착).
- **현장 등장 요소:** 덤프트럭, 신호수, 다른 작업자, 매설물 표지. 트럭 진입 타이밍과 신호에 맞춰 작업해야 한다.
- **생산성 지표:** 시간당 굴착량(m³/h), 사이클 시간, 대기 시간
- **시나리오 확장:** 현장과 과제는 데이터(JSON)로 정의해, 기관이 지역 현장 유형에 맞게 새 시나리오를 추가할 수 있게 한다.

### 5.5 안전 절차는 독립 채점 항목

직업훈련 시뮬레이터가 게임과 다른 핵심 차이다. 레벨마다 **필수 안전 항목**이 있고, 하나라도 위반하면 점수와 관계없이 불합격시킬 수 있다(치명 항목).

- 시동 전: 외관 점검, 안전벨트 착용, 안전레버 확인
- 작업 중: 선회·주행 전 경음기, 선회 반경 내 작업자 진입 감지, 경사면 자세, 버킷 위로 사람·차량 통과 금지
- 지하 매설물·가공선(고압선) 근접 경고
- 작업 종료: 버킷 지면 하강, 안전레버 잠금, 시동 정지

## 6. 채점 엔진 (레벨 진행과 수료의 기반)

모든 과제는 **이벤트 → 규칙 → 점수** 구조로 평가한다. 규칙은 JSON으로 정의하므로 강사가 기준을 조정할 수 있다.

| 평가 축 | 측정 방법 |
|---|---|
| 시간 | 과제 시작부터 완료까지 |
| 정확도 | 목표 깊이·체적·위치 대비 오차 (높이맵 비교) |
| 효율 | 사이클당 적재량, 불필요한 동작 수 |
| 흘림·손실 | 버킷 밖으로 떨어진 토사 부피 |
| 부드러움 | 레버 입력 급변(저크), 버킷 충격. 키보드는 입력 특성이 달라 **입력 방식별 기준값**을 따로 둔다 |
| 충돌 | 장비, 구조물, 트럭, 라인 접촉 |
| 안전 | §5.5 항목 위반. 치명 항목은 즉시 불합격 |
| 품질 (실무 과정) | 설계 지형 대비 과굴착·미굴착 체적 |
| 생산성 (실무 과정) | 시간당 굴착량, 사이클 시간 |

- 모든 세션은 **입력·상태 로그**로 저장하고 **리플레이**를 지원한다. 강사 피드백과 이의 확인에 쓴다.
- 결과 화면에는 점수 분해, 약점 항목, 추천 재연습 과제를 보여 준다.

## 7. 수료증·뱃지·등급

### 7.1 등급 체계 (안)

| 과정 | 등급 | 명칭(안) | 조건 | 뱃지 | 발급 |
|---|---|---|---|---|---|
| ① 자격증 | 1 | **입문 운전자** | L0~L2 통과 | 브론즈 | 뱃지 |
| ① 자격증 | 2 | **기초 운전자** | L3~L4 통과 | 실버 | 뱃지 |
| ① 자격증 | 3 | **자격 준비 운전자** | L5 모의 실기시험 3회 연속 합격 | 골드 | **자격증 과정 수료증** |
| ② 실무 | 4 | **현장 실무 운전자** | W1~W3 통과, 안전 위반 0 | 플래티넘 | 뱃지 |
| ② 실무 | 5 | **위험작업 운전자** | W4 통과, 안전사고 0 | 다이아몬드 | 뱃지 |
| ② 실무 | 6 | **숙련 운전자(마스터)** | W5 통과 + 종합 상위 기준 | 마스터 | **실무 과정 수료증** |

- 수료증은 과정마다 하나씩, **자격증 과정 수료증**과 **실무 과정 수료증** 두 종류다. 그 사이 등급은 뱃지로 표시한다.
- 과제 단위 **세부 뱃지**도 둔다. 예: "무흘림 적재", "정밀 트렌치", "무사고 100회", "모의시험 최단 기록", "과굴착 0".
- **입력 방식:** 조이스틱과 키보드 모두 모든 레벨, 뱃지, 수료증을 획득할 수 있다. 입력 방식은 기록과 수료증에 표시만 한다.
- 수료증 내용: 훈련생명, 과정과 등급, 이수 과제, 총 훈련 시간, **주 입력 방식**, 발급일, 기관명, **고유 번호와 QR**. QR을 찍으면 진위 확인 페이지가 열린다.
- **고지 문구 필수:** "본 수료증은 ○○기관의 시뮬레이터 교육과정 이수 증명이며, 국가기술자격(굴착기운전기능사)을 대체하지 않습니다."

### 7.2 강사·기관 대시보드

- 훈련생 등록과 반 편성, 진도와 점수 추이, 약점 분석
- 과제 기준값 조정, 수료증 발급 승인, 리플레이 열람
- 실제 자격증 보유 확인 처리 (확인되면 실무 과정 바로 해금)
- **강사 개입 모드:** 훈련 중인 화면을 실시간으로 보고, 돌발 상황(작업자 진입, 장비 경고, 날씨 변화)을 직접 투입한다. 실무 과정 W4·W5에서 쓴다.

### 7.3 교육 효과 검증

시뮬레이터가 실제로 도움이 되는지 수치로 확인한다. 기관 보고나 사업 지원 신청에도 필요한 자료다.

| 지표 | 측정 방법 |
|---|---|
| 실제 실기시험 합격률 | 시뮬레이터 수료생과 미사용 훈련생의 합격률 비교 (훈련생 동의 후 결과 입력) |
| 모의시험 ↔ 실제 시험 일치도 | 모의시험 점수가 높은 훈련생이 실제로도 합격하는지 확인. 낮으면 채점 기준 조정 |
| 실장비 교육 시간 절감 | 실장비 실습 전 시뮬레이터 이수 시, 실장비에서 같은 수준에 이르는 시간 비교 |
| 강사·훈련생 만족도 | 과정별 설문 (조작감, 현장 현실감, 난이도) |

- P2 이후 소규모 시범 운영(훈련생 5~10명)으로 첫 자료를 모으고, 결과에 따라 난이도와 채점 기준을 조정한다.

### 8.2 P0 진행 상황 (2026-11-25)

키보드로 굴착 → 선회 → 덤프 한 사이클이 동작한다. 실행 방법은 `README.md`, 교육생 리뷰 반영 내용은 `docs/리뷰/반영-기록.md`에 있다.

| §8.1 점검 항목 | 상태 |
|---|---|
| 키보드만으로 1사이클을 1분 안에 | ✅ 시범 운전 약 16초, 키보드 직접 조작 약 21초 (자동 테스트와 브라우저에서 확인) |
| 같은 입력 기록을 재생하면 같은 결과 | ✅ 자동 테스트, 화면의 재생 검증(T 키) |
| 부피 보존 오차 1% 이내 | ✅ 3사이클 뒤 오차 0에 가까움 (10⁻¹³ % 수준) |

계획과 달라진 점: Havok 물리엔진은 P0에 넣지 않았다. P0 현장에는 부딪힐 물체가 없어서다. 장애물·덤프트럭이 나오는 P1 이후에 연결한다. 메뉴가 없어 React도 아직 쓰지 않았다.

### 8.3 P1 진행 상황 (2026-11-25)

P1을 임시 수치로 시작했다. 과정의 뼈대와 레벨 0~3이 동작한다.

| P1 산출물 | 상태 |
|---|---|
| 과제·채점 구조 (과제 정의, 과제 심판, 채점표, 합격선·실격) | ✅ |
| 과정 메뉴, 과제 설명, 결과 화면, 진도 저장·해금, 등급(브론즈) | ✅ 기록은 브라우저 안에만 저장 |
| L0 입문: 퀴즈 7문제, 시동~종료 12단계 절차 | ✅ |
| L1 기초 조작 4과제, L2 복합 조작 2과제 | ✅ |
| L3 굴착 작업 연습 4과제 (L3-3은 버킷 통과 구역 높이 연습, L3-4는 통과 구역 지나 4사이클, 시험 방식) | ✅ 수치는 임시 |
| L4 코스 운전 연습 | ⬜ |
| L5 모의 실기시험 (감독관 안내, 실격 조건, 시험 채점표) | ⬜ |

임시로 정한 수치 (공식 규격 확인 뒤 `src/curriculum/excavatorLicense.ts`에서 바꾼다):

| 항목 | 임시 값 |
|---|---|
| 버킷 통과 구역: 아래 줄 / 위쪽 통과 제한선 | 1.3m / 4.0m |
| L3-4 사이클 수 / 제한 시간 | 4사이클 / 4분 |
| L3-4 통과 구역 접촉 | 1회당 안전 점수 5점 감점, 3회 실격 (실제 시험은 1회 실격으로 알려져 있음) |
| 합격선 | 100점 만점 60점 (레벨 0은 100점) |
| 굴착 과제 배점 | 작업량 40, 흘림 20, 시간 25, 안전 15 |

**확인이 필요한 것:** 굴착기운전기능사 실기의 코스 운전은 타이어식 굴착기(핸들, 가속 페달, 브레이크)로 보는 것으로 알고 있다. 맞다면 L4에는 지금의 크롤러 주행과 다른 주행 모델과 운전석(핸들·페달)이 필요하다. 큐넷 공개문제나 교육기관을 통해 확인해야 한다.

**P0을 먼저 끝내야 하는 이유:** 버킷-토사 표현이 부족하면 그 위에 쌓을 모든 것의 가치가 떨어진다. P0 결과에 따라 엔진이나 물리 방식 변경 여부를 판단한다.

### 8.1 P0 상세 범위

**만드는 것**
1. 평지 연습장 1곳(높이맵 지형, 흙 쌓을 지정 구역 표시)
2. 단순 형태 굴착기 1대(박스·실린더 조합): 붐·암·버킷·선회·좌우 궤도 주행
3. §3.4의 운동 모델(유량 분배, 가감속, 굴착 저항)과 토사 모델(굴착, 흘림, 덤프, 안식각)
4. 입력: 키보드(가상 레버, 가속 램프, Shift 미세 조작) → USB 조이스틱 2개 → 페달 순서
5. 운전석 시점과 외부 시점 전환, 가상 레버 기울기 표시
6. 간이 측정 화면: 사이클 시간, 버킷 적재량, 흘림량, 부피 보존 오차

**만들지 않는 것:** 메뉴, 계정, 레벨, 수료증, 실제 3D 모델, 소리(엔진음 정도만 선택)

**완료 판단 (점검 목록)**
- [ ] 키보드만으로 굴착 → 선회 → 덤프 1사이클을 1분 안에 할 수 있다
- [ ] 같은 입력 기록을 두 번 재생하면 결과(적재량, 흘림량)가 같다
- [ ] 부피 보존 오차가 1% 이내다
- [ ] 저사양 기준 PC에서 60fps(최소 30fps)를 유지한다
- [ ] 대상 조이스틱·페달이 Tauri 설치판에서 인식되고 비례 입력이 동작한다
- [ ] 굴착기 운전 경험자 1명 이상이 "동작 순서와 감각이 교육용으로 쓸 만하다"고 평가한다

## 10. 결정이 필요한 사항

1. **개발 주체:** Claude Code 중심 소규모 개발(본 계획 전제)인가, 3D 아티스트가 포함된 팀인가? 엔진 선택이 이것으로 결정된다.
2. **하드웨어 예산과 좌석 수:** 교육장 1곳당 몇 대, 조이스틱·페달 등급, 다중 모니터 여부
3. **운영 방식:** 교육장 오프라인 단독, 기관 서버, 클라우드 중 무엇인가
4. **기준 장비 급:** 시험장·교육장에서 주로 쓰는 굴착기 급(톤수, 버킷 용량, 크롤러/타이어식). 운동 모델의 기본 제원이 이것으로 정해진다
5. **레버 패턴 기본값:** 기관에서 가르치는 표준 패턴 (키보드 배치도 이 패턴을 따름)
6. **필기 모의고사 문제 출처:** 자체 제작할지, 이용 허락을 받은 문제를 쓸지
7. **시험 규격 확정:** 큐넷 공개자료 확보, 또는 교육기관 담당자의 기준 제공
8. **수료증 발급 주체와 명칭:** 기관명, 등급 명칭 최종안
9. **지게차(`Jigecha`) 시뮬레이터 동시 개발 여부:** 동시 개발한다면 §3.2의 공통 코어를 처음부터 분리한다.
